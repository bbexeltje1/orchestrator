CHANGE IN v1.1.2 (first real Windows run reconciliation)
--------------------------------------------------------
Field results from Windows 10 / PS 5.1.19041 / Python 3.12.10 validated the
v1.1.1 changes: the stdin config bridge works on PS 5.1, disabled services
report "disabled in config (not contacted)", llama-server was detected and
the exact start line was printed, config reported correctly.

Fixed (all three found in the field log):
  1. Offline-test output was invisible: Invoke-OfflineTests ran pytest
     inside a function whose output the caller captures
     ($offline = Invoke-OfflineTests), so the entire pytest output was
     swallowed. It is now sent to the console via Out-Host and copied to
     logs\pytest-output.txt via Tee-Object.
  2. Stray True/False lines in the report: bare Test-* probe calls leaked
     their boolean return values to the console. All probe call sites now
     pipe to Out-Null.
  3. Ollama signature verification was too strict for pre-installed
     binaries: real machines report UnknownError/NotTrusted when the
     chain/revocation check cannot complete (offline CRL, proxy, security
     software) even for a genuine Ollama install. Pre-installed binaries
     are now accepted when the signer certificate matches Ollama and
     there is no evidence of tampering (HashMismatch/NotSigned still
     refuse); downloaded installers keep the strict Valid-only check
     before execution.

Still open: the underlying offline-test failure on the Windows box (exit
code 1 = real assertion failure, collection was fine). Its output was
hidden by bug 1; re-run and capture logs\pytest-output.txt.

preserved below.

CHANGE IN v1.1.1 (Windows diagnostic reconciliation)
----------------------------------------------------
Reconciled against real Windows 10 / Windows PowerShell 5.1 diagnostics.

Fixed:
  1. Config upgrade path: a config/config.yaml written by v1.0.x is now
     upgraded in place on startup ("init --upgrade"): missing sections
     (notably "services" with qwen_start_command) are appended, existing
     keys, values and comments are never touched. This closes the "config
     has no qwen_start_command setting" finding for upgraded installs.
  2. Windows PowerShell 5.1 native-argument quoting bug: Get-ServicesConfig
     passed Python code containing double quotes via "python -c", which
     PS 5.1 mangles (embedded quotes are not escaped). The snippet is now
     piped on stdin ("python -"), which is immune to the bug. Verified
     against the exact extracted snippet, including the v1.0.x-config and
     env-override cases.
  3. stop.ps1 PID-reuse guard: every recorded PID is re-verified against
     its recorded process name AND command line before anything is
     stopped; a PID that cannot be positively identified as started by
     the launcher is left strictly alone.
  4. Disabled services are never started or contacted: auto-start now
     honours qwen/thx/omniroute/arena "enabled" flags. A disabled service
     reports NOT CONFIGURED / SKIPPED "disabled in config (not contacted)"
     instead of being probed. OmniRoute is never enabled automatically;
     no Arena dispatch occurs (workflow.dry_run remains true).
  5. PS 5.1 TLS: TLS 1.2 is forced on for Invoke-WebRequest so the
     pypi/python.org/ollama.com calls work on stock Windows PowerShell 5.1.
  6. Qwen startup configuration guidance: when qwen_start_command is empty
     and llama-server(.exe) is on PATH, the launcher prints the exact line
     to paste. It never guesses a model path and never starts a guessed
     command.

Kept as-is (per requirements): workflow.dry_run=true, omniroute.enabled
false, no model downloads during testing, existing Ollama/llama.cpp
installations detected and never modified, already-running services only
probed.
